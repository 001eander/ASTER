# 评估体系诊断：现有评估与旗舰跑批数据的失效模式

Issue: 001eander/ASTER #133（决策地图 #128 下的 research ticket）。分支 `research/eval-diagnosis`，一次性研究分支，不开 PR、不合并。

## 结论摘要

1. 33 条提案里没有一条在 schema / 前视 / 复杂度上硬失败（0/33），失败全部发生在指标门控：**23/25 条失败提案的 icir 不达标**，rank_ic 4 条，max_corr 2 条，mono 1 条。门控实际只筛"IC 日间稳定度"这一条卡线。
2. 沙盒里的门控阈值在跑批中途改过一次（icir >= 0.5 改成 icir >= 0.3），而这个 0.5 从未进过仓库；仓库历史上是 0.2，现在 TASK.md 与代码是 0.3。**同一批产物在不同阈值下失败集合从 25 条变到 20 条**，事后无法从 score.json 复现当时的判据。
3. 全样本单一卡线掩盖了因子的年度失稳：26 个 pool 因子按逐年口径（rank_ic >= 0.02 且 icir >= 0.3）能连续 6 年过线的只有 2 个；4 个因子出现过 IC 符号翻转；最严重的 `vol_cv_20_neg` 全样本 IC +0.0286，最差年只有 +0.0113（衰减 60%）。
4. 评分函数 `score = rank_ic x max(0, 1 - max_corr/0.7)` 被共线性折扣主导：折扣吃掉 IC 的 68.5%，score 与折扣的秩相关 +0.737、与 quality 只有 +0.243。过线 8 条的 score 中位 0.0102，未过线 25 条中位 0.0103，**score 对"是否过线"没有区分度**（卡线在 ICIR，score 里没有 ICIR）。
5. `max_corr` 是相对量（相对当前库），随库增长漂移：同一因子复核后折扣掉 0.14-0.31，score 从 0.0140 掉到 0.0035；反向地，把今天的库当基准，33 条提案里有 8 条的 max_corr 现在超过 0.7（例如 0008 记录 0.47，现在 0.90）。
6. 查重拦不住换皮的四种形态：符号翻转（`vol_ratio_5` 与 `vol_ratio_5_20_neg`，|corr| 0.79）、窗口平移（`overnight_intraday_spread_20` 与 `_60`，0.618，被放行）、等价变换（`mom_5` 与 `ma_bias_10`，0.9265）、权重微调（提案 0008 与 0013，0.965）。库内已有 8 对 |corr| > 0.7 的因子同时在 pool 里；按现行整库规则跑一遍，pool 会从 26 收到 13（聚簇降 6 个、容量上限再降 7 个，13 个手工种子全部出局）。
7. `mono > 0` 形同虚设：33 条里只有 1 条不满足（且它同时卡在 rank_ic/icir），5 层 Spearman 的取值本身是离散的（1.0/0.9/0.8...）。
8. 相对 QuantaAlpha，我们缺的是样本外分层（train/valid/test）、逐年 IC 报告、池级合成评估、结构性冗余闸、显著性检验、压力区间与迁移分析。这些层都不需要新数据，可以在 2021-09-29 起的现有样本上落地。

## 诊断口径

数据与样本：

| 项 | 值 |
|---|---|
| 行情 | `data/bars/2021.parquet` ~ `2026.parquet`，2021-09-29 至 2026-09-29，6,312,680 行，5,759 只证券 |
| 交易日 | 合计 1,212 天；逐年 2021: 63、2022: 242、2023: 242、2024: 242、2025: 243、2026: 180 |
| 标签 | `quant.labels.open_to_open_label(horizon=1)`，T+1 开盘 -> T+2 开盘后复权收益 |
| 库内因子 | `factor_library/registry.json`，26 个 `status=pool`（13 个 gen-0 种子 + 13 个内循环 gen-1） |
| 提案 | `runs/flagship-mining/eb/solutions/0001..0033/solution/factor.py`，33 条 |

指标口径复用仓库内核，不另造语义：

- RankIC：`quant.eval.metrics.ic_series(method="spearman")` 的逐日截面秩相关，有效证券数 >= 30 的日子计入，时间序列均值即 `rank_ic_mean`，`mean/std` 即 `icir`。
- 行为相关：`quant.factor_lib.correlation.cross_section_corr` 的逐日截面 Pearson 时间序列均值，两两取绝对值最大者即 `max_corr`。
- 门控与折扣源码：`quant/eval/factor.py` 的 `RANK_IC_MIN=0.02`、`ICIR_MIN=0.3`、`MONO_MIN=0.0`、`MAX_CORR_REJECT=0.7`、`_corr_discount`。

复算实现：59 个因子（26 库内 + 33 提案）在全样本面板上各算一遍，按 `(date, instrument)` 对齐落盘为日内 z-score（Pearson 与秩对日内仿射变换不变，由此避开 float32 量化误差），逐日截面用 pairwise-complete 的矩公式复算 RankIC 与两两 Pearson。

与仓库内核的一致性校验：

| 校验项 | 结果 |
|---|---|
| 逐年 RankIC（内核 vs 复算，10 个因子 x 6 年 + 全样本，共 70 组） | 偏差 <= 1.2e-4；仅离散取值的 `p0018` 有 2.6e-4 ~ 7.9e-4 的系统偏差 |
| 两两行为相关（`cross_section_corr` vs 复算，2024 段 7 对） | 4 位小数一致，例如 `mom_5 x ma_bias_10` 0.9259 / 0.9259、`vol_ratio_5 x vol_ratio_5_20_neg` -0.7955 / -0.7955 |
| 库内因子 registry 记录 vs 复算全样本 | 一致，例如 `mom_5` 记录 IC -0.02697 / icir -0.1749，复算 -0.02697 / -0.1750 |

对照说明：`d_validate.py` 里曾把 2024 子集上的因子重算值与全样本复算值对比，出现最大 0.009 的相关偏差，定位为"因子在子面板上重算引入的窗口起头差异"，与相关算子无关；本报告所有数字均取全样本复算。

# 失效模式 1：指标门控把失败集中在 icir 一条卡线上，且阈值中途变更

## 数据证据

硬失败 0/33。`runs/flagship-mining/eb/index.jsonl` 33 条全部 `ok: true` 并带 `score.notes`；`quant/eval/factor.py` 的硬失败路径不写 score.json、以非 0 退出码表达，33 个方案目录里都有 score 产物；转录中检索不到"截断重算检出前视""schema 不符"的记录（"复杂度超标"只在 `solve.sh` 源码文本里命中）。中间尝试没有完整落盘（19/33 个 inspiration 的转录留有评估输出，共 66 次评估、17 次过线），因此硬失败率只对最终产物成立。

门控阈值在跑批中途改过一次，转录里有直接证据：

| 时段（提案号 / 时间） | 门控阈值（转录原话） | 折扣公式（notes 文本） |
|---|---|---|
| 0001-0015 / 09-30 16:25-18:10 | "the gate needs rank_ic_mean >= 0.02, icir >= 0.5"、"icir 0.43 < 0.5" | `(1-0.51)`，即 `1 - max_corr` |
| 0016-0033 / 09-30 23:19 起 | "gate ... requires rank_ic >= 0.02, icir >= 0.3" | `(1-0.37/0.70)`，即 `1 - max_corr/0.7` |

仓库侧的门控历史与沙盒不一致：`db5e31f`（issue #27）里 `ICIR_MIN = 0.2`，`6032121`（#119，10-12）才改成 0.3，TASK.md 现在写 0.3。**0.5 这个值从未进入仓库**，只存在于当时的沙盒镜像里。

按当时口径复算的失败归因（25 条失败，可叠加）：

| 失败项 | 条数 | 说明 |
|---|---|---|
| icir | 23 | 0001-0015 全部（icir 落在 0.14-0.48，全部 < 0.5）；0016、0017、0022、0023、0024、0025、0026、0029 |
| rank_ic | 4 | 0007（0.0163）、0016（-0.0003）、0017（0.0038）、0029（0.0145） |
| max_corr | 2 | 0019（0.88）、0031（0.75） |
| mono | 1 | 0029（-0.5） |

其中 19 条失败提案只差 icir 一项：前 15 条里的 14 条（只有 0007 同时卡 rank_ic），加上 0022、0023、0024、0025、0026。把阈值统一成现在的 0.3/0.02/0.7 复算（`max_corr` 用当前库、剔除自身副本）：

| 口径 | 过线提案数 | 变化 |
|---|---|---|
| 当时实际口径（前 15 条用 0.5，后 18 条用 0.3） | 8 / 33 | 基准 |
| 统一按现在的 0.02 / 0.3 / mono>0 / 0.7 | 13 / 33 | 0001、0002、0005、0011、0015 从记录失败转为过线；0008、0010、0012、0013、0014 的 IC 与 ICIR 达标，但 max_corr 随库增长涨到 0.82-0.90，失败原因由 icir 改为 max_corr |

入库 13 条 = 8 条按当时门控过线 + 5 条（0001、0002、0005、0011、0015）门控失败后经 `score_promoted.json` 复核重新评估通过。这 13 条与库内副本的源码关系：9 条逐字节相同（0001、0002、0005、0011、0015、0018、0020、0030、0033），4 条有小幅编辑。其中 `0021` 与库内 `volume_spike_freq_20_neg` 差 14 行并含语义变化（`min_samples` 从 60 改为 40），`0028` 差 16 行，`0027`、`0032` 各差 2 行。这批复核入库说明"人工复核 + 复算"这条路径在起作用，标准化的门控并没有筛掉它们；同时提示库内条目的 `metrics` 记录可能来自与库内源码不一致的那一版（`0021` 的逐年 IC 与库内副本已经对不上）。

## 对评估设计的含义

- 门控阈值必须有单一真源，并随产物落盘（例如 score.json 增加 `thresholds` 与 `scorer_version` 字段）。现在的产物无法回答"这条当时为什么被判失败"，跨批次的成绩也不可比。
- 失败集中在一根 ICIR 卡线上，说明其他几道闸门（schema、前视、复杂度、共线性）在真实数据上几乎空转；评估体系的设计重点应放在"用哪几个指标、在哪段数据上卡"，继续加校验层的边际收益很低。
- icir 卡线主导迭代方向：转录显示 0010-0015 连续 6 轮的灵感方向就是"抬 ICIR"（时序平滑、加腿、截面中性化、两档加权、改窗口），见失效模式 4 的搜索轨迹。

- 逐年（或分段）IC/ICIR 报告应作为评估的固定输出，即使不直接卡线，也要在上线前回答"这个信号在哪一年不成立"。
- ICIR 卡线若保留，判据应改成"分段 ICIR 的最低值或过线年数"，例如"6 年中至少 5 年过线"，把 `return_skew_20_neg` 这类只在部分年份成立的因子与 `four_leg_ensemble_rank` 区分开。
- 2021（63 天）只能当预热带，不能当验证段；可用年份的分层建议见失效模式 5。

# 失效模式 3：评分被共线性折扣主导，与门控判据脱节

## 数据证据

过线因子的 score 贴地：记录口径 8 条过线因子的 score 为 0.0132、0.0128、0.0114、0.0106、0.0098、0.0069、0.0051、0.0019（中位 0.0102），来自 quality（rank_ic）0.0218-0.0439 被折扣压到 4%-56%。

折扣主导排序（33 条记录值）：

| 统计 | 值 |
|---|---|
| quality 均值 / 中位 | +0.0307 / +0.0301 |
| 折扣 `max(0,1-max_corr/0.7)` 均值 / 中位 | 0.343 / 0.343 |
| 折扣 < 0.5 的提案数 | 27 |
| 折扣 < 0.2 的提案数 | 9 |
| 折扣吃掉的 IC 比例 `1 - mean(score)/mean(quality)` | 68.5% |
| score 与 quality 的秩相关 | +0.243 |
| score 与折扣的秩相关 | +0.737 |

单看 IC 的前三名 `0019`（IC +0.0510、max_corr 0.88）、`0031`（+0.0500、0.75）、`0030`（+0.0439、0.67）在 score 排序里落到第 32、31、29 名，得分 0.0000、0.0000、0.0019。全场 IC 最高的两条被判 0 分。

score 与门控结果无关：

| 分组 | 条数 | quality 中位 | 折扣中位 | score 中位 |
|---|---|---|---|---|
| 记录口径过线 | 8 | 0.0304 | 0.357 | 0.0102 |
| 记录口径未过线 | 25 | 0.0286 | 0.343 | 0.0103 |

三列几乎重合。卡线在 icir，score 里没有 icir，agent 看到的梯度与它是否过关没有可分辨的关系。

`mono > 0` 形同虚设：33 条里只有 `0029`（mono -0.5）不满足，且它同时卡在 rank_ic 与 icir。mono >= 0.6 占 87.9%，mono >= 0.9 占 72.7%。取值本身离散（1.0、0.9、0.8、0.7、0.6、0.4、0.3、0.2、-0.5），因为它是 5 个分层跨日平均收益对层号的 Spearman，只有 5 个点，且跨日平均已经抹掉时间结构。

|---|---|---|---|---|---|
| 0001 | 0.51 | 0.61 | 0.0140 | 0.0035 | -0.149 |
| 0002 | 0.46 | 0.68 | 0.0221 | 0.0012 | -0.313 |
| 0005 | 0.38 | 0.50 | 0.0236 | 0.0107 | -0.174 |
| 0015 | 0.42 | 0.63 | 0.0213 | 0.0038 | -0.296 |
| 0028 | 0.46 | 0.66 | 0.0106 | 0.0018 | -0.286 |

反向也成立：以今天的库为基准，33 条提案里 8 条的 `max_corr` 超过 0.7，其中 `0008` 从记录 0.47 涨到 0.90、`0014` 0.44 -> 0.82、`0013` 0.46 -> 0.85、`0012` 0.35 -> 0.82、`0010` 0.49 -> 0.85、`0007` 0.32 -> 0.74、`0019` 0.88、`0031` 0.75。这些因子在入库时点合法，现在会被判冗余。

## 对评估设计的含义

- 奖励信号里的折扣项压掉的正好是高 IC 信号，agent 从梯度里学到的是"离已有因子远一点"，与"提高预测力"无关。折扣项的存在有其理由（避免同质化），但它不该是 score 的支配项。
- score 应与门控判据同源。要么让门控成为 score 的一部分（不过线即 0 或负），要么把 ICIR 与稳定性写进 score，否则"评分"和"过关"是两套说法。
- `max_corr` 需要固定参考池（冻结快照或指定验证窗）并保留版本号，否则同一因子的 score 会随时间单调衰减，跨批次成绩不可比。
- `mono` 门控可以删掉或替换成分年 IC 同号率、IC 的 t 统计这类真正有区分度的稳定性指标。

- 参考池应冻结（快照或指定窗口，例如 2024 选择期），并记录版本，避免阈值随库增长漂移。
- 阈值需要配套置信区间或分年一致率，同时给出"库内已有冗余对"的处理路径（先整库再入库），否则门槛对被池内冗余挤占的新因子不公平。

# 失效模式 5：评估缺少样本外与池级层，奖励信号指向"库内差异"

## 数据证据：与 QuantaAlpha 的分层对照

QuantaAlpha（arXiv:2602.07085v3，5.1、5.4、A.1、A.2、4.1.2）的评估分层：

- 时序切分：CSI300 train 2016-01-01 ~ 2020-12-31 / valid 2021-01-01 ~ 2021-12-31 / test 2022-01-01 ~ 2025-12-26。
- 指标：IC（Pearson）、ICIR、RankIC、RankICIR；策略层 ARR、IR、MDD，全部为成本后超额。
- 显著性：966 个测试日上给 t 统计、p 值、95% 置信区间、正 IC 日占比（例：IC 均值 0.0426，正 IC 日 60.04%，t 7.23，p 4.95e-13）。
- 池级评估：约 150 个通过验证的因子送入同一个 LightGBM，论文里报告的 IC 0.0472 是池级指标，不是单因子最优值。
- 生成期门控：语义一致性（假设、符号表达、代码三者互校）、复杂度 `C(f) = SL + PC + log(1+|F_f|)`（符号长度、自由参数个数、特征数）、结构性冗余（AST 最大公共子树规模，超过阈值即重写）。
- 功能冗余：在 2021 验证面板上做输出相关过滤，越线两条保留 RankIC 高的一条。
- 分析层：逐年 IC/RankIC 对比（2021-2025）、压力区间（2025-04 高波动段）、跨市场迁移（CSI500、S&P500）。

对照我们的现状与可用年份：

| 层 | QuantaAlpha | ASTER 现状 | 落到我们数据上的建议 |
|---|---|---|---|
| 时序分层 | train 2016-2020 / valid 2021 / test 2022-2025 | 无，全样本 2021-09-29 起 | 开发 2021-09-29 ~ 2023-12-29（547 天），选择/验证 2024-01-02 ~ 2024-12-31（242 天），样本外 2025-01-02 ~ 2026-09-29（423 天）。2021 只剩 63 天，只能当预热带 |
| 逐年 IC/ICIR | 有（2021-2025 逐年图） | 门控只有全样本一条 | 固定输出 2022-2026 逐年值，2021 标注为不完整年；可用滚动 12 个月窗替代单年 |
| 池级合成评估 | 约 150 因子 + LightGBM | 单因子门控；AutoGluon 在 `quant/automl/`，未接入挖掘奖励 | 用现有 AutoGluon 与 `quant/backtest` 做池级增量 IC / 残差 IC，在 2024 选择期算、2025-2026 验 |
| 结构冗余闸 | AST 子树同构 + 自由参数计数 | 无；复杂度只看圈复杂度（<=15）、AST 节点（<=500）、字段数 | 立即可做，不需要新数据 |
| 行为冗余的参考面板 | 2021 验证面板 | 全样本、入库时点、参考池随库增长 | 用 2024 选择期或冻结日快照 |
| 一致性校验 | 假设-符号-代码 LLM 互校 | 无 | 可选，复用 `prompts/` 做 hypothesis 与实现的复核 |
| 显著性 | t 统计 / p 值 / 95% CI / 正 IC 日占比 | 只有 n_days 与 icir | 数据够（1,190 天），立即可加 |
| 压力区间与迁移 | 2025-04 高波动、跨市场 | 无 | 2025-04 段已有数据；跨池可换沪深300 / 中证1000 成分 |
| 成本后策略指标进评分 | ARR / IR / MDD 在评估协议内 | 在 `quant/backtest`，与因子门控分离 | 复用现有回测与费用口径 |

## 数据证据：奖励信号指向哪里

33 条提案的记录值对照后段表现：

| 对照 | 截面秩相关 |
|---|---|
| 记录 score vs 2025-2026 平均 IC | +0.418 |
| 记录 rank_ic vs 2025-2026 平均 IC | +0.955 |
| 记录 icir vs 2025-2026 平均 IC | +0.777 |

IC 本身在跨因子层面高度可外推（+0.955），但被优化的 score 只有 +0.418，因为它主要反映"与库的差异度"（失效模式 3）。换句话说，评估体系把最可外推的维度（IC）按 0.243 的权重计分，把随库漂移的维度（折扣）按 0.737 的权重计分。

内循环的目标也不是池级预测力：TASK.md 的任务过关线是"库内 gen >= 1 且指标满足单因子过关线的因子累计达到 10 个"，转录里 agent 反复在数"6 个 / 8 个过线因子"。这条目标把"凑够 10 个互不相关的单因子"当终点，与组合层要的"目标持仓的样本外表现"之间没有连接。

## 对评估设计的含义

- 缺的第一层是样本外分层。没有它，任何阈值都只能说明"在这段历史上成立"，无法回答 2025-2026 是否延续。
- 缺的第二层是池级目标。单因子过关线可以留作初筛，奖励信号应换成"加入池后样本外的增量"（残差 IC、池级 ICIR、组合层 IR），否则 agent 会一直朝着"库内差异"优化。
- 缺的第三层是稳定性与显著性。当前的 icir 是全样本日 IC 的 mean/std，对年度结构性差异不敏感；补上逐年值、t 统计、正 IC 日占比之后，"合格"才有统计含义。
- 结构性冗余与参数计数属于生成期约束，成本低、收益直接，可以和其他层并行推进。
